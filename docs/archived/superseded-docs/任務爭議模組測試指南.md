## 👤 方式二：手動測試

### 前置準備

1. **確保服務運行**
   ```bash
   # 啟動後端服務
   cd backend && php -S localhost:8888
   
   # 啟動 Flutter App (另一個終端)
   flutter run
   
   # 啟動 Admin Web (另一個終端)
   cd admin/frontend && npm run dev
   ```

2. **準備測試帳號**
   - 用戶帳號：具有有效任務的用戶
   - 管理員帳號：具有管理權限的管理員

## 📱 Flutter App 手動測試

### 測試流程 A：爭議提交

1. **進入任務聊天室**
   - 登入 Flutter App
   - 導航至 `/chat`
   - 選擇一個進行中的任務聊天室
   - 點擊進入 `/chat/detail`

2. **測試爭議按鈕**
   - 確認 Action Bar 中有 'dispute' 按鈕
   - 點擊 'dispute' 按鈕

3. **測試爭議對話框**
   - 驗證 `DisputeDialog` 正確開啟
   - 檢查是否顯示防重複提交檢查
   - 如果已有爭議，應顯示現有爭議資訊

4. **測試表單提交**
   - 填寫爭議標題 (10-100字)
   - 填寫爭議描述 (20-500字)
   - 點擊提交按鈕
   - 驗證提交成功訊息

5. **驗證狀態更新**
   - 確認任務狀態更新為 'dispute'
   - 檢查是否有系統訊息發送
   - 驗證再次點擊 'dispute' 顯示現有爭議

### 測試流程 B：防重複提交

1. **重複提交測試**
   - 在已提交爭議的聊天室中
   - 再次點擊 'dispute' 按鈕
   - 應顯示現有爭議資訊而非提交表單

2. **驗證顯示內容**
   - 爭議 ID
   - 爭議狀態
   - 提交時間
   - "無法重複提交" 提示

## 🖥️ Admin Web 手動測試

### 測試流程 C：爭議管理

1. **訪問爭議列表**
   - 登入管理員後台
   - 點擊側邊欄 "Task Disputes"
   - 導航至 `/task-disputes`

2. **測試列表功能**
   - 驗證爭議列表正確載入
   - 測試分頁功能
   - 測試狀態篩選
   - 測試日期範圍篩選
   - 測試排序功能

3. **測試統計資料**
   - 檢查總爭議數
   - 檢查各狀態統計
   - 檢查今日新增數量

### 測試流程 D：爭議處理

1. **查看爭議詳情**
   - 點擊爭議列表中的 "Detail" 按鈕
   - 驗證 `DisputeDetailDialog` 正確顯示
   - 檢查爭議基本資訊

2. **查看聊天室**
   - 點擊 "View Chat" 按鈕
   - 導航至 `/task-disputes/{disputeId}/chat-room`
   - 驗證聊天記錄正確載入

3. **測試聊天室功能**
   - 檢查訊息歷史完整性
   - 驗證用戶資訊正確顯示
   - 確認只讀模式 (無輸入框)
   - 測試訊息類型渲染 (文字、圖片、系統訊息)

4. **測試決策功能**
   - 點擊 "Resolve" 按鈕
   - 選擇決策結果：
     - `completed` - 任務完成
     - `back_to_progress` - 退回進行中
     - `reset` - 重置任務
   - 填寫決策說明
   - 提交決策

5. **驗證決策結果**
   - 檢查爭議狀態更新為 'resolved'
   - 驗證任務狀態正確更新
   - 確認系統訊息發送
   - 檢查管理員操作記錄

## 🔍 資料庫驗證測試

### 手動 SQL 檢查

```sql
-- 檢查爭議記錄
SELECT * FROM task_dispute_events ORDER BY created_at DESC LIMIT 5;

-- 檢查爭議日誌
SELECT * FROM task_dispute_event_logs ORDER BY created_at DESC LIMIT 5;

-- 檢查任務狀態
SELECT id, title, status_id FROM tasks WHERE status_id = 4;

-- 檢查聊天訊息
SELECT * FROM chat_messages WHERE kind = 'system' ORDER BY created_at DESC LIMIT 5;

-- 檢查管理員操作記錄
SELECT * FROM admin_active_logs WHERE action LIKE '%dispute%' ORDER BY created_at DESC LIMIT 5;
```

## 🚨 錯誤情境測試

### 測試異常情況

1. **無效資料測試**
   - 提交空白標題/描述
   - 提交超長內容
   - 使用無效的任務 ID

2. **權限測試**
   - 無 JWT token 訪問
   - 過期 token 測試
   - 非管理員訪問管理員 API

3. **業務邏輯測試**
   - 對已完成任務提交爭議
   - 對已取消任務提交爭議
   - 重複決策同一爭議

4. **網路異常測試**
   - API 超時處理
   - 網路中斷恢復
   - 伺服器錯誤回應

## 📞 測試支援

如果在測試過程中遇到問題，請檢查：

1. **日誌文件**
   - `backend/logs/` 目錄下的錯誤日誌
   - Flutter 控制台輸出
   - 瀏覽器開發者工具

2. **常見問題**
   - JWT token 是否有效
   - 資料庫連接是否正常
   - API 端點是否可訪問

3. **除錯工具**
   - `test_dispute_api.php` - API 連通性測試
   - `test_dispute_e2e.php` - 完整流程測試
   - 資料庫 SQL 查詢驗證
