MVP 需求總覽（Admin 後台）

A. Dashboard
	•	卡片：Pending review users（統計 users.permission = 0 的數量）
	•	可點進 Users 模組做審核

B. Users 模組（側欄手風琴）

/users（列表）
	•	欄位：id, name, display_name, points, permission, status
	•	支援搜尋(名稱/email)與排序(updated_at desc)

/users/:id（詳細）
	•	顯示：基本資料、student_id 相關欄位（含學生證圖片預覽）
	•	狀態操作：
	•	批准：permission: 0 → 1；同時生成 users.referral_code（唯一、短碼）
	•	暫停：設 permission = -2
	•	軟刪除：設 permission = -4
	•	解鎖：-2/-4 → 1
	•	發送重設密碼信（email flow，見下）
	•	每次操作 寫入 admin_logs 與（必要時）user_active_log

/user-logs
	•	僅檢視 user_active_log
	•	支援依 user_id 篩選、依 created_at/updated_at desc 排序

C. Tasks 模組（側欄手風琴）

/tasks（列表）
	•	所有 tasks，updated_at desc
	•	可搜尋/篩選：狀態、建立者

/tasks/:id（詳細）
	•	基本資料 + 關聯（applications、room、participant 等）
	•	若狀態是 pending confirmation：
	•	顯示：status_changed_at 與 deadline_at = status_changed_at + 7 days
	•	倒數：僅顯示（真正到期處理交給 cron/worker）
	•	Dispute：若有人發起爭議，顯示爭議狀態與連結（chat_rooms.type='dispute'）
	•	在Dispute狀態的任務，管理員有將 dispute 批准：同意該任務直接視作完成(tasks.status_id = 5), 或是駁回爭議，將該任務轉回原本的任務狀態	

/task-logs
	•	顯示 task_logs（desc），欄：task_id, action, actor, created_at, metadata

D. Payment 模組（側欄手風琴）

/payment-requests（入點數申請）
	•	來源：point_deposit_requests（待審核）
	•	Actions：
	•	Approve：將 amount 正式加進 users.points；寫 point_transactions（入帳）；紀錄 approver_id 與備註
	•	Reject：更新狀態+備註
	•	每次操作 寫 admin_logs

/payment-settings
	•	任務完成手續費設定（task_completion_points_fee_settings）
	•	顯示最新 is_active=1 的唯一手續費
	•	新增一筆（rate, description, updated_by），同時將其他舊資料 is_active=0
	•	寫 admin_logs
	•	官方收款銀行帳戶（official_bank_accounts）
	•	列表、新增、設 is_active=1（同時將其他改 0）
	•	寫 admin_logs

/fee-income-logs
	•	fee_revenue_ledger 列表（desc）+ 匯總總額

E. Support 模組（側欄手風琴）
	•	先預留導覽與路由
	•	/support/chat/detail：指向客服聊天室（chat_rooms.type='support'）
	•	/issues：列表 support_events（點擊進聊天室）

建議一案一房：每張客訴 = 一個 chat_room（support），最單純的 MVP 作法

F. Admin 模組（側欄手風琴）

/admin-logs
	•	admin_logs（desc）

/admins
	•	列出 admins：名稱、角色
	•	權限：
	•	super_admin：可改所有管理員角色
	•	admin：可改其他人（但不可改 super_admin）
	•	所有操作 寫 admin_logs

資料模型 & 必要補強

以下為「MVP 最小可行」補強與欄位建議。

users
	•	建議欄位：id, name, display_name, email (unique), permission, status, points, referral_code (unique), payment_password (hash), created_at, updated_at, deleted_at (nullable)
	•	流程：
	•	註冊完成 → permission=0
	•	審核通過 → permission=1 並生成 referral_code
	•	暫停/軟刪除 → permission=-2/-4

student_id
	•	user_id (unique), school_name, student_number, images (json or 1:N 附檔表), verified_at (nullable)

tasks
	•	必備：status_id / status_code, status_changed_at, deadline_at (for pending_confirmation +7d), creator_id, participant_id (nullable), reward_point
	•	建議索引：(status_id, deadline_at)

task_applications
	•	task_id, user_id, status (applied/rejected/withdrawn/accepted/cancelled), created_at, updated_at

chat_rooms
	•	id, type ('task'|'support'|'dispute'), task_id (nullable), title, creator_id, participant_id, created_at

chat_messages
	•	room_id, from_user_id (nullable for system), kind ('user'|'system'), message, created_at
	•	未讀算法沿用 chat_reads（room_id, user_id, last_read_message_id）

point_deposit_requests
	•	id, user_id, amount, status (pending/approved/rejected), approver_id, note, created_at, updated_at

point_transactions
	•	id, user_id, amount (+/-), type (deposit/withdraw/transfer_in/transfer_out/fee), related_task_id, actor_id, description, created_at

task_completion_points_fee_settings
	•	id, rate (decimal), description, is_active(0/1), updated_by, created_at
	•	唯一 is_active=1；新增新紀錄時將其他改 0

official_bank_accounts
	•	id, bank_name, account_name, account_number_masked, is_active(0/1), created_at
	•	保證唯一 active

fee_revenue_ledger
	•	id, task_id, user_id (payer), amount, rate, created_at

user_active_log
	•	id, user_id, actor_type('user'|'admin'|system), actor_id, action, field, old_value, new_value, reason, metadata(json), ip, created_at

admin_logs
	•	id, admin_id, action, target_type, target_id, changes(json), created_at
	•	例：action='approve_user'、target_type='user'、target_id=123

support_events（建議）
	•	id, user_id, room_id, subject, category, status(open/in_progress/waiting_customer/resolved/closed), accepted_by (admin_id), created_at, updated_at, closed_at
	•	建立 ticket 同步建立 chat_room(type='support') + 首則訊息 + system message

password_resets（新增，for email 重設）
	•	id, user_id, token (unique, 32-64字), expires_at, used_at (nullable), created_at
	•	用於 email reset link（見下）

核心流程（MVP）

1) 使用者審核
	•	條件：users.permission=0 → 後台 /users/:id 有「批准」按鈕
	•	成功：permission=1、referral_code 產生（唯一短碼）
	•	admin_logs + user_active_log 記錄

2) 點數入帳（Payment Requests）
	•	Admin 在 /payment-requests 審核
	•	Approve：
	•	users.points += amount
	•	point_transactions（type=deposit）
	•	approver_id, note
	•	admin_logs
	•	Reject：更新狀態 + 備註 + admin_logs

3) 任務完成付款（Confirm & Pay）
	•	付款碼驗證 → 轉移 tasks.reward_point 給 participant → 扣服務費 → 記帳：
	•	point_transactions 三筆：發佈者轉出、接受者轉入、發佈者支付手續費（若 rate>0）
	•	fee_revenue_ledger 記錄（rate, amount, task_id, payer）
	•	成功後 才：tasks.status_id=5 (completed)
	•	發送 chat_messages.kind='system' 與 WebSocket

4) Pending Confirmation 倒數
	•	狀態切到 pending_confirmation 時，記 status_changed_at、算 deadline_at = +7d
	•	cron/worker 每 10 分鐘掃 WHERE status='pending_confirmation' AND deadline_at<=NOW() → 自動撥款（等同 Confirm & Pay；扣費+轉移+紀錄+系統訊息）

5) 支援／客服（Support）
	•	/contact-us：上方新建 ticket（subject/category/描述/附件）→ 建 support_events + 建 chat_room (support) + 首則訊息 + system message，導至聊天室
	•	後台：/issues 列表 → Accept → status='in_progress' + accepted_by
	•	解決：客服點 resolve；客戶可點 close

Email 重設密碼（MVP 做法）

資料表：password_resets
	•	user_id, token (unique), expires_at (15~30 分), used_at (nullable), created_at
	•	token 建議 32~64 bytes（hex/base64url）

流程
	1.	使用者在登入頁按「忘記密碼」→ 輸入 email
	2.	後端產生 token，插入 password_resets；寄信（含連結）
	•	連結：https://yourdomain/reset-password?token=...
	3.	前端打開頁面，輸入新密碼 → POST /auth/reset-password 搭 token
	4.	後端：
	•	驗 token 是否存在、未過期、未使用
	•	更新 users.password_hash
	•	設 password_resets.used_at = NOW()；使 token 作廢
	5.	風險控管：
	•	每 email 每日限 5 次申請
	•	寄信內容避免洩漏「帳號不存在」

寄信方式
	•	cPanel 的 SMTP（如 no-reply@yourdomain）
	•	PHP：PHPMailer；Flutter：不要直接寄，交給 API
	•	信模板：HTML + i18n（最少英文/中文）
