# 聊天室檢舉狀態檢查功能實作報告

## 📋 **功能描述**

在 `/chat/detail` 頁面的 Action Bar 中，當用戶點擊 "Report" 按鈕時，系統會優先檢查當前用戶是否已經檢舉過該聊天室。如果已經檢舉過，則顯示 "Already Reported" 提示對話框，而不是顯示檢舉表單。

## 🔍 **實現邏輯**

### 1. **後端 API 實現**

#### **新增 API 端點**: `backend/api/chat/check_report.php`
- **方法**: GET
- **功能**: 檢查用戶是否已經檢舉過特定聊天室
- **參數**: `room_id` (查詢參數)
- **返回**: 
  ```json
  {
    "success": true,
    "data": {
      "has_reported": true/false,
      "room_id": "123",
      "report_id": "456", // 僅在已檢舉時返回
      "reported_at": "2025-08-30 10:30:00" // 僅在已檢舉時返回
    }
  }
  ```

#### **核心邏輯**:
1. **權限驗證**: 檢查用戶是否有權限訪問該聊天室
2. **資料表檢查**: 檢查 `chat_reports` 表是否存在
3. **檢舉記錄查詢**: 查詢該用戶是否已經檢舉過該聊天室
4. **結果返回**: 返回檢舉狀態和相關資訊

### 2. **前端服務實現**

#### **新增方法**: `ChatService.checkReportStatus()`
```dart
Future<Map<String, dynamic>> checkReportStatus({
  required String roomId,
}) async
```

#### **功能**:
- 調用後端 API 檢查檢舉狀態
- 處理錯誤情況和網路異常
- 返回標準化的檢舉狀態數據

### 3. **UI 邏輯實現**

#### **修改方法**: `ChatDetailPage._openReportSheet()`
- **檢查流程**: 
  1. 獲取當前聊天室 ID
  2. 調用 `ChatService.checkReportStatus()` 檢查檢舉狀態
  3. 根據結果決定顯示內容

#### **顯示邏輯**:
- **已檢舉**: 顯示 "Already Reported" 對話框
  - 標題: "Already Reported" (帶綠色勾選圖標)
  - 內容: "You have already reported this chat room. Our team will review your report and take appropriate action."
  - 按鈕: "OK"

- **未檢舉**: 顯示原有的檢舉表單
  - 原因選擇 (Abusive behavior, Spam or scam, Harassment, Request Dispute)
  - 描述輸入 (最少 10 字元)
  - 提交按鈕

## 🗄️ **資料庫結構**

### **chat_reports 表**
```sql
CREATE TABLE IF NOT EXISTS chat_reports (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  room_id BIGINT UNSIGNED NOT NULL,
  reporter_id BIGINT UNSIGNED NOT NULL,
  reason VARCHAR(64) NOT NULL,
  description TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### **關鍵欄位**:
- `room_id`: 被檢舉的聊天室 ID
- `reporter_id`: 檢舉者用戶 ID
- `reason`: 檢舉原因
- `description`: 檢舉詳細描述
- `created_at`: 檢舉時間

## 🔧 **技術實現細節**

### 1. **錯誤處理**
- **API 錯誤**: 如果檢查檢舉狀態失敗，顯示錯誤提示
- **權限錯誤**: 如果用戶無權限訪問聊天室，返回 404
- **資料表不存在**: 如果 `chat_reports` 表不存在，假設用戶未檢舉過

### 2. **安全性考慮**
- **權限驗證**: 確保用戶只能檢查自己有權限的聊天室
- **JWT 驗證**: 所有 API 調用都需要有效的 JWT token
- **SQL 注入防護**: 使用參數化查詢

### 3. **用戶體驗優化**
- **載入狀態**: 檢查過程中顯示適當的載入提示
- **錯誤提示**: 清晰的錯誤訊息和處理建議
- **一致性**: 與現有檢舉流程保持一致的使用者介面

## 📊 **測試案例**

### 1. **首次檢舉**
- **步驟**: 用戶首次點擊 Report 按鈕
- **預期**: 顯示檢舉表單
- **驗證**: 可以正常填寫和提交檢舉

### 2. **重複檢舉**
- **步驟**: 用戶再次點擊 Report 按鈕
- **預期**: 顯示 "Already Reported" 對話框
- **驗證**: 不顯示檢舉表單

### 3. **權限驗證**
- **步驟**: 嘗試檢舉無權限的聊天室
- **預期**: 返回 404 錯誤
- **驗證**: 前端顯示適當的錯誤提示

### 4. **網路異常**
- **步驟**: 在網路異常情況下點擊 Report
- **預期**: 顯示網路錯誤提示
- **驗證**: 用戶可以重試或稍後再試
